# ShopEase catalogue and run notes

## Start the application

Run from the project directory:

```powershell
mvn spring-boot:run
```

Open **http://localhost:8081/**. Keep the Spring Boot process running while browsing; the frontend uses same-origin `/api` requests. If the app is stopped, the page now explains how to reconnect rather than leaving a generic fetch error.

## Seed demo products

The database seeder is opt-in. Start Spring Boot with:

```powershell
mvn spring-boot:run "-Dspring-boot.run.arguments=--shopease.seed-demo-catalog=true"
```

Or run the packaged app:

```powershell
java -jar target/shopease-verify/online-shopping-cart-0.0.1-SNAPSHOT.jar --shopease.seed-demo-catalog=true
```

It adds 56 deterministic products across 14 categories, skips existing matching names, and never deletes or replaces existing products. It upgrades metadata only for rows matching the seeder's own exact brand, category, and generated description. Running it repeatedly is safe.

## Database changes

The existing `spring.jpa.hibernate.ddl-auto=update` setting remains in place, with the same MySQL URL, database, credentials, and port. Hibernate adds nullable product columns `brand`, `image_url`, `original_price`, `rating`, `review_count`, and `created_at`, plus a `cart_items` table with a unique cart-token/product key and lookup index. Existing product rows are preserved. Existing old in-memory carts cannot be migrated because they were never written to the database.

Cart rows store a random browser token, product ID, and quantity. The token is sent in an HTTP-only, SameSite=Lax cookie that lasts 30 days. Product names and prices are read from the product table for display and totals. This makes a cart survive reloads and Spring Boot restarts; different browser profiles receive separate carts. Clearing the cart removes its database rows.

Seeded prices, original/list prices, ratings, and review counts are demo data. The UI marks ratings and savings as demo information. Existing products without an image URL use a product-specific SVG generated by the app from the product name and category. These are local illustrations, not product photographs. Set `imageUrl` to a licensed photo URL or local static path when photography is available; the illustration remains as an image-failure fallback.

## Demo-only features

Guest browsing is enabled; account sign-in is not. Wishlist selections are kept in that browser's local storage. Checkout validates the demo form but does not create an order, save contact details, reserve inventory, or process payment. No payment details are requested.
